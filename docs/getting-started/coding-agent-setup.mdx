## Management MCP server

The Management MCP server lets your coding agent manage integrations and connections, call tools, read logs, and search the Nango docs. See the [Management MCP reference](/reference/backend/management-mcp#tools) for the full tools list and required permissions.

It connects with OAuth and follows your Nango user permissions across the environments in your account. The server uses Client ID Metadata Documents (CIMD) and doesn't support Dynamic Client Registration (DCR).

<a id="oauth-recommended"></a>
<Tabs>
  <Tab title="Claude Code">
    **From the directory:** Add the [Nango connector from the Claude directory](https://claude.ai/directory/3822f3b8-11cd-4f4c-bbe7-2a9ec6be28b9) and complete the authorization.

    **Manual setup:** Add the server for your user so it is available across projects.

    ```bash
    claude mcp add --transport http nango-management --scope user https://mcp.nango.dev/mcp
    claude mcp login nango-management
    ```

    Complete the Nango authorization in the browser, then run `claude mcp list` to verify the connection.
  </Tab>

  <Tab title="Codex">
    Add the following to `~/.codex/config.toml` for a global configuration, or `.codex/config.toml` for a project configuration:

    ```toml
    [mcp_servers.nango-management]
    url = "https://mcp.nango.dev/mcp"
    ```

    Start the OAuth flow:

    ```bash
    codex mcp login nango-management
    ```

    Complete the Nango authorization in the browser, then use `/mcp` to verify the connection.
  </Tab>

  <Tab title="VS Code">
    Run **MCP: Open User Configuration** from the Command Palette, then add the server:

    ```json
    {
      "servers": {
        "nangoManagement": {
          "type": "http",
          "url": "https://mcp.nango.dev/mcp"
        }
      }
    }
    ```

    Select **Start** above the server configuration. VS Code opens the Nango authorization page in your browser. Complete the authorization, then check that the server is running.
  </Tab>
</Tabs>

<Note>
For CI/CD pipelines and clients that don't support CIMD yet, connect with an [Environment API key](/reference/backend/management-mcp#use-an-api-key-instead) instead.
</Note>

## Other agent tools

These resources help agents discover Nango docs, provider slugs, API shapes, and how to build functions.

| Tool | URL | Use it for |
| --- | --- | --- |
| Docs MCP server | `https://nango.dev/docs/mcp` | Live docs context without authentication. The Management MCP server includes the same docs tools. |
| `llms.txt` | `https://nango.dev/docs/llms.txt` | Compact index of core Nango docs for LLM context windows. |
| `llms-full.txt` | `https://nango.dev/docs/llms-full.txt` | Full generated docs text for deeper offline context. |
| `api-catalog.txt` | `https://nango.dev/docs/api-catalog.txt` | Provider and integration slug discovery. |
| OpenAPI spec | `https://nango.dev/docs/spec.yaml` | Exact HTTP API schemas for code generation or typed clients. |
| Nango skills | [NangoHQ/skills](https://github.com/NangoHQ/skills) | Building custom functions. See [build with a coding agent](/guides/platform/functions/functions-guide#build-with-a-coding-agent). |
