Agent sessions are an optimized interface for AI agents to use integrations. Connect your agent to Nango once through MCP to access 1,300+ APIs.

- **10,000+ ready-to-use tools.** Nango keeps them up to date and improves them using insights from hundreds of millions of production calls.
- **Fewer tokens.** On-demand tool search and concise tool responses keep the agent's context small.
- **You control access.** Choose whose accounts the agent uses and what it can do. The agent never sees provider API credentials.
- **Traceable calls.** See what the agent called and why in Nango Logs.

## How sessions work

Your backend creates a session and gives the agent an MCP URL and a scoped token.

- **[Tenant](/guides/agent-sessions/tenant)** selects whose connections the agent can use.
- **[Toolset](/guides/agent-sessions/toolsets)** selects which integrations and tools it can call.
- **[Meta tools](/guides/agent-sessions/meta-tools)** let it find and run tools and connect integrations.

## Quickstart

<Steps>
  <Step id="create-session" title="Create a session from your backend">
  By default, a session covers every tool on the integrations the tenant has a connection for.

  To define the tenant, select the connections the agent may use with tag selectors:
  ```bash
  curl --request POST \
    --url 'https://api.nango.dev/sessions' \
    --header 'Authorization: Bearer <NANGO-API-KEY>' \
    --header 'Content-Type: application/json' \
    --data '{
      "tenant": {
        "connections": {
          "any": [{ "tags": { "organization_id": "acme", "workspace": "marketing" } }]
        }
      }
    }'
  ```

  Requires an API key with the `environment:agent_sessions:write` scope. See [API key scopes](/reference/backend/http-api/api-keys#scopes).

  This returns a ready-to-use session:
  ```json
  {
    "data": {
      "session_id": "0f4a...",
      "session_token": "nango_agent_session_...",
      "mcp_url": "https://api.nango.dev/session/0f4a.../mcp",
      "expires_at": "2026-09-15T10:00:00.000Z",
      "toolset": {
        "notion": { "connected": true, "tools_pinned": 0, "tools_searchable": 12 },
        "slack": { "connected": true, "tools_pinned": 0, "tools_searchable": 7 }
      },
      "meta_tools": { "nango_tool_search": true, "nango_execute": true, "nango_proxy": false }
    }
  }
  ```
  </Step>
  <Step id="pass-mcp" title="Pass the MCP server to your agent">
  Pass the `mcp_url` to your agent, with the `session_token` as bearer auth:

  <Tabs>
    <Tab title="OpenAI">
    ```typescript
    import OpenAI from "openai";

    const client = new OpenAI();

    const response = await client.responses.create({
      model: "gpt-5.6",
      input: "Summarize the last 5 emails in the user's inbox",
      tools: [
        {
          type: "mcp",
          server_label: "nango", // Or a name suitable for your session
          server_url: "<mcp_url>",
          authorization: "<session_token>",
          require_approval: "never"
        }
      ]
    });

    console.log(response.output_text);
    ```

    The Responses API never stores the `authorization` value, so send it on every request.

    const mcpClient = await createMCPClient({

        type: "http",
        url: "<mcp_url>",
        headers: { Authorization: "Bearer <session_token>" }
      }
    });

    try {
      const { text } = await generateText({

        tools: await mcpClient.tools(),

      });

      console.log(text);
    } finally {
      await mcpClient.close();
    }

## Session basics

### Creating a session

Set the tenant, toolset, and session lifetime when you create a session.

```jsonc
{
  "tenant": {
    "connections": {  // Provide tags, pinned connections, or both
      "any": [
        { "tags": { "organization_id": "acme" } }
      ],
      "pinned": [
        { "integration_id": "notion", "connection_id": "882386f9-efae-48aa-bea1-58a4f6fbc2ff" }
      ]
    }
  },

  "toolset": {  // Defaults to integrations with tenant connections
    "notion": { "allow": { "tools": ["read_doc", "upsert_doc"] } },
    "slack": "*"
  },

  "pinned_tools": {  // Defaults to no pinned tools
    "notion": ["read_doc"]
  },

  "meta_tools": {
    "nango_tool_search": true,
    "nango_execute": true,
    "nango_proxy": false
  },

  "expires_in": "1h" // Defaults to 15d. Range: 60s to 15d.
}
```

See [Tenant](/guides/agent-sessions/tenant), [Toolsets & tools](/guides/agent-sessions/toolsets), and [Meta tools](/guides/agent-sessions/meta-tools) for configuration options.

Session creation fails if the tenant [matches multiple connections for an integration without a pin](/guides/agent-sessions/tenant#resolving-ambiguity), or if the toolset names an unknown integration or tool.

Nango returns a `session_id` and a scoped `session_token`. Treat the token as a secret and set the shortest lifetime your agent needs.

### Session MCP server

Connect to the session's `mcp_url` over Streamable HTTP with `session_token` as the bearer token.

`tools/list` returns enabled meta tools and pinned tools, 50 per page. Pass `nextCursor` to fetch the next page. Call pinned tools by name and put their arguments in `input`. The agent can find unpinned tools with [`nango_tool_search`](/guides/agent-sessions/meta-tools#nango_tool_search) and call them with [`nango_execute`](/guides/agent-sessions/meta-tools#nango_execute).

### Tool changes

Tool availability and schemas [can change during a session](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#capabilities), including for meta tools. Fetch tool definitions from the session's MCP server at runtime. Do not hardcode tool names or schemas.

- If an error suggests a tool is unavailable or its schema may have changed, [refresh the tool definitions](https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/caching#time-to-live-ttl-field) before retrying.
- [Pass tool errors to the model](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#error-handling) so it can adjust the call.

### Terminating a session

Sessions expire after `expires_in`. Create a new session if you need more time. To end a session early, call `DELETE /sessions/{session_id}`.

```bash
curl --request DELETE \
  --url 'https://api.nango.dev/sessions/0f4a...' \
  --header 'Authorization: Bearer <NANGO-API-KEY>'
```

Requires an API key with the `environment:agent_sessions:write` scope, the same one session creation uses.

```json
{
  "data": {
    "session_id": "0f4a...",
    "ended_at": "2026-09-15T10:00:00.000Z",
    "reason": "terminated"
  }
}
```

Termination revokes the session token. New MCP requests return `401`, and calls already in progress can finish.

Repeating the request returns the original `ended_at` and `reason`. An unknown session or a session in another environment returns `404`.
