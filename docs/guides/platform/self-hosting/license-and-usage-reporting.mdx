If you run Nango Self-Managed, install the license Nango sends you and configure your instance to send usage metrics each day. If your installation can't reach Nango, you can export the metrics as a file instead.

<Note>
If you run BYOC, Nango sets up licensing and reporting for you. See [BYOC](/guides/platform/self-hosting/byoc).
</Note>

## What Nango gives you

When Nango registers your instance, you'll receive three things.

| Value | What it is | Secret |
| --- | --- | --- |
| License | A signed document that identifies your installation and lists its expiration date and entitlements | Keep it private |
| Installation key | The private key your instance uses to sign reports. Save it when you receive it. Nango keeps only the public key and can't resend the private key | Yes |
| Installations URL | The endpoint that receives your reports. Nango also gives you its static IP addresses | No |

## Requirements

- Nango managed image `managed-X.Y.Z` or later.
- [Helm chart](https://github.com/NangoHQ/nango-helm-charts) `2.6.0` or later, which adds the `selfHosting` workload.
- For automatic reporting, allow outbound HTTPS on port 443 to the installations URL. Use the static IP addresses from Nango if you restrict egress. For clusters without outbound access, see [Report without outbound access](#report-without-outbound-access).

## Set it up

<Steps>
  <Step id="store-license-and-key" title="Store the license and the installation key">
    Create a Kubernetes secret in the namespace where Nango runs. The example uses the `nango` namespace and assumes you saved the license as `license.txt` and the key as `installation-key.pem`.

    ```bash
    kubectl create secret generic nango-installation -n nango \
      --from-file=NANGO_LICENSE=./license.txt \
      --from-file=NANGO_INSTALLATION_PRIVATE_KEY=./installation-key.pem
    ```

    If you sync Kubernetes secrets from a secret manager, add both entries there.
  </Step>
  <Step id="check-license-on-server" title="Give the license to the server">
    The server checks the license every time it starts. Add this to your Helm values so it can read it.

    ```yaml
    server:
      extraEnvVars:
        - name: NANGO_LICENSE
          valueFrom:
            secretKeyRef:
              name: nango-installation
              key: NANGO_LICENSE
    ```
  </Step>
  <Step id="enable-self-hosting-workload" title="Configure the reporting workload">
    The `selfHosting` workload reads metrics from your database. Add the settings below to your Helm values and replace the URL placeholder with the installations URL Nango gave you. If you're exporting metrics manually, you can omit `FLAG_HOSTED_TELEMETRY_UPLOAD_ENABLED` and `NANGO_INSTALLATIONS_API_URL`.

    ```yaml
    selfHosting:
      enabled: true
      extraEnvVarsSecrets:
        - nango-installation
      extraEnvVars:
        - name: FLAG_HOSTED_TELEMETRY_UPLOAD_ENABLED
          value: "true"
        - name: NANGO_INSTALLATIONS_API_URL
          value: "<the installations URL from Nango>"
    ```

    Give `selfHosting` the same database settings as your other services. Set `NANGO_DATABASE_URL` or the `NANGO_DB_*` variables, along with `NANGO_DB_SSL` if your main database requires TLS. If you store metrics in a separate database, use the same telemetry database URL and TLS settings on `selfHosting` as on the services that write the metrics. See [Hosted telemetry](/guides/platform/self-hosting/self-managed#hosted-telemetry).
  </Step>
  <Step id="check-it-works" title="Verify the rollout">
    After you deploy the updated Helm values, check the server logs for the license status. If you enabled automatic reporting, check the `selfHosting` logs for upload activity.

    | Service | Log line | Meaning |
    | --- | --- | --- |
    | server | `License for <name> (<installation id>) is valid until <date>.` | The license is installed and verified |
    | self-hosting | `Uploading telemetry to <installations URL>` | The uploader started |
    | self-hosting | `Uploaded <metric> for <day>` | Nango received the report for that metric and day. Can take up to an hour after the rollout |

    {/* TODO(pau): describe the license status view once it ships. */}
  </Step>
</Steps>

## What Nango receives and when

Each report covers one metric for one UTC day. Each row contains a timestamp, a metric name, a value, and a random ID for the process that recorded it. See [Hosted telemetry](/guides/platform/self-hosting/self-managed#hosted-telemetry).

A report is a gzip-compressed file with one JSON object per line: a header, then the rows.

```json
{"kind":"header","installation_id":"9b2f6c1e-4d3a-4f7b-8a51-0c2e7d9f4b16","metric":"nango.hosted_metric.active_concurrency.max","from":"2026-11-18T00:00:00.000Z","to":"2026-11-19T00:00:00.000Z"}
{"kind":"row","ts":"2026-11-18T00:00:25.255Z","metric":"nango.hosted_metric.active_concurrency.max","attributes":{"producer_id":"5f2a9c1e"},"value":3}
{"kind":"row","ts":"2026-11-18T00:01:25.255Z","metric":"nango.hosted_metric.active_concurrency.max","attributes":{"producer_id":"5f2a9c1e"},"value":2}
```

- A day is sent once it has ended, within an hour after 00:15 UTC.
- The first time it runs, the uploader sends the last 30 days.
- If an upload fails, the uploader tries again every hour.

## Report without outbound access

If your instance cannot call the installations URL, export the metrics as a file and send it to Nango.

The export is protected by a key that you create and that stays with you. Generate one, for example with `openssl rand -hex 32`, store it as `NANGO_HOSTED_TELEMETRY_MANUAL_EXPORT_KEY` in the `nango-installation` secret, and restart the `selfHosting` workload.

The `selfHosting` service then serves the export on port `3010`. Call it from wherever you reach your internal services:

```bash
curl -fsS -o nango-telemetry.ndjson.gz \
  -H "Authorization: Bearer <export key>" \
  "http://<selfHosting service>:3010/v1/telemetry/export?from=2026-11-01&to=2026-12-01"
```

`from` and `to` are UTC dates. The export includes `from` and excludes `to`, so the example covers November. A file holds at most 31 days.

The export is a gzip-compressed NDJSON file. Nango uses the signature to verify that the file came from your installation and is intact.

## Renew the license or replace the key

When Nango sends you a new license, replace `NANGO_LICENSE` in the secret and restart the server and the `selfHosting` workload. Both read it at startup.

What the server logs at startup, for each state of the license:

| State | Server | Reporting |
| --- | --- | --- |
| Valid | Logs `License for <name> (<id>) is valid until <date>.` | Runs |
| Expired, in the grace period | Logs `License for <name> (<id>) expired on <date>. Renew it before <date>.` | Runs |
| Past the grace period | Logs `License check failed: license for <name> expired on <date> and its grace period ended on <date>.` | Uploads stop and the export endpoint returns `403` |

To replace the installation key, ask Nango for a new one, replace `NANGO_INSTALLATION_PRIVATE_KEY` in the secret and restart the `selfHosting` workload.

## Troubleshooting

| Service | Log line | Cause | Fix |
| --- | --- | --- | --- |
| server | `License check failed: NANGO_LICENSE is not set.` | The server has no license | Add `NANGO_LICENSE` to the server |
| server | `License check failed: <reason>.` | The license failed verification | Check the `NANGO_LICENSE` value in the secret, or ask Nango to send the license again |
| self-hosting | `Skipping (<reason>)` | A setting is missing or unusable. The reason names it | Fix the setting it names and restart the workload |
| self-hosting | `Uploading stopped. The rest will be uploaded later`, with `could not reach …` | The uploader couldn't connect to the installations URL | Check the URL and make sure your cluster allows outbound HTTPS to the IP addresses Nango gave you |
| self-hosting | `Uploading stopped. The rest will be uploaded later`, with `Nango answered 401` or `403` | Nango rejected the request | Contact Nango with the error message. The uploader retries automatically |
| self-hosting | `Not uploading (the grace period of the license ended on …)` | The license expired and its grace period is over | Renew the license |
