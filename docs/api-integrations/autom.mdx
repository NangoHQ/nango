## 🚀 Quickstart

Connect to Autom with Nango and see data flow in 2 minutes.

<Steps>
    <Step id="create-integration" title="Create the integration">
    In Nango ([free signup](https://app.nango.dev)), go to **Integrations** -> _Configure New Integration_ -> _Autom_.
    </Step>
    <Step id="authorize-autom" title="Authorize Autom">
    Go to **Connections** -> _Add Test Connection_ -> _Authorize_, then enter your Autom API key. Later, you'll let your users do the same directly from your app.
    </Step>
    <Step id="call-autom-api" title="Call the Autom API">
    Let's make your first request to the Autom API to get your usage and remaining credits. This call does not consume credits. Replace the placeholders below with your [Environment API key](/reference/backend/http-api/api-keys), integration ID, and connection ID:
    <Tabs>
        <Tab title="cURL">

            ```bash
            curl "https://api.nango.dev/proxy/v1/usage" \
              -H "Authorization: Bearer <NANGO-API-KEY>" \
              -H "Provider-Config-Key: <INTEGRATION-ID>" \
              -H "Connection-Id: <CONNECTION-ID>"
            ```

        </Tab>

        <Tab title="Node">

        Install Nango's backend SDK with `npm i @nangohq/node`. Then run:

        ```typescript
        import { Nango } from '@nangohq/node';

        const nango = new Nango({ apiKey: '<NANGO-API-KEY>' });

        const res = await nango.get({
            endpoint: '/v1/usage',
            providerConfigKey: '<INTEGRATION-ID>',
            connectionId: '<CONNECTION-ID>'
        });

        console.log(res.data);
        ```
        </Tab>
    </Tabs>

    Or fetch credentials with the [Node SDK](/reference/backend/backend-sdk/node#get-a-connection-with-credentials) or [API](/reference/backend/http-api/connections/get).

    ✅ You're connected! Check the **Logs** tab in Nango to inspect requests.
    </Step>

    <Step id="implement-in-app" title="Implement Nango in your app">
        Follow our [quickstart](/getting-started/quickstart) to integrate Nango in your app.
    </Step>
</Steps>

## API gotchas

- Rate limit errors return `401`, not `429`, just like an invalid key. Only the error message tells them apart: rate limit errors start with `Rate limit exceeded`.
- Repeated failed authentication attempts from the same IP return `403` with `IP temporarily blocked`.
- Successful requests deduct credits from your balance, and `402` means you need more credits. `GET /v1/usage` does not consume credits.
