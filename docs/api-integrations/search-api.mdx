## 🚀 Quickstart

Connect to SearchApi with Nango and see data flow in 2 minutes.

<Steps>
    <Step id="create-integration" title="Create the integration">
    In Nango ([free signup](https://app.nango.dev)), go to **Integrations** -> _Configure New Integration_ -> _SearchApi_.
    </Step>
    <Step id="authorize-search-api" title="Authorize SearchApi">
    Go to **Connections** -> _Add Test Connection_ -> _Authorize_, then enter your SearchApi API key. Later, you'll let your users do the same directly from your app.
    </Step>
    <Step id="call-search-api-api" title="Call the SearchApi API">
    Let's make your first request to the SearchApi API to get your account usage. Replace the placeholders below with your [Environment API key](/reference/backend/http-api/api-keys), integration ID, and connection ID:
    <Tabs>
        <Tab title="cURL">

            ```bash
            curl "https://api.nango.dev/proxy/v1/me" \
              -H "Authorization: Bearer <NANGO-API-KEY>" \
              -H "Provider-Config-Key: <INTEGRATION-ID>" \
              -H "Connection-Id: <CONNECTION-ID>"
            ```

        </Tab>

        <Tab title="Node">

        Install Nango's backend SDK with `npm i @nangohq/node`. Then run:

        ```typescript
        import { Nango } from '@nangohq/node';

        const nango = new Nango({ apiKey: '<NANGO-API-KEY>' });

        const res = await nango.get({
            endpoint: '/v1/me',
            providerConfigKey: '<INTEGRATION-ID>',
            connectionId: '<CONNECTION-ID>'
        });

        console.log(res.data);
        ```
        </Tab>
    </Tabs>

    Or fetch credentials with the [Node SDK](/reference/backend/backend-sdk/node#get-a-connection-with-credentials) or [API](/reference/backend/http-api/connections/get).

    ✅ You're connected! Check the **Logs** tab in Nango to inspect requests.
    </Step>

    <Step id="implement-nango" title="Implement Nango in your app">
        Follow our [quickstart](/getting-started/quickstart) to integrate Nango in your app.
    </Step>
</Steps>

## API gotchas

- Nango sends the key as `Authorization: Bearer <key>`. SearchApi also accepts the `api_key` query parameter, but the header keeps the key out of URLs and logs.
- All engines (Google, Bing, Amazon, YouTube and others) share the `/v1/search` endpoint. Pick one with the required `engine` query parameter, for example `/v1/search?engine=google&q=nango`.
- You can use at most 20% of your plan's credits each hour. The [Account API](https://www.searchapi.io/docs/account-api) (`/v1/me`) returns `searches_this_hour` and `hourly_rate_limit`. Only searches that return a `200` are billed. See [Pricing](https://www.searchapi.io/pricing).
- Large `next_page_token` values can make a `GET` fail with a `413` or `414`. Send a `POST` to `/v1/search` with the parameters in the JSON body instead.
- The API key only works on the REST API. The [MCP server](https://www.searchapi.io/integrations/mcp) uses its own authentication (OAuth or an MCP token).
