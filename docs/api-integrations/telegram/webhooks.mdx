## How it works

1. Telegram sends a POST request to your Nango webhook URL for each update to your bot, for example a new message.
2. Nango looks up the connection named by the `nangoConnectionId` query param on the webhook URL and checks that the `X-Telegram-Bot-Api-Secret-Token` header matches that connection's own webhook secret. Telegram doesn't sign updates; it sends back the `secret_token` you set with `setWebhook`.
3. Nango routes the update to that connection, using the update's kind, the field next to `update_id` such as `message` or `callback_query`, as the webhook type.

Telegram updates don't say which bot they are for, so each connection needs its own webhook in Telegram and its own `webhookSecret` in Nango. Webhooks without the right secret are rejected, unless the connection has no secret and **Allow unverified webhooks** is on in the integration's settings.

## Setup

### 1. Choose a webhook secret

Generate a random secret of at least 16 characters using only `A-Z`, `a-z`, `0-9`, `_` and `-`, which Telegram allows, for example with `openssl rand -hex 24`, and store it as `webhookSecret` in the connection's metadata:

```bash
curl -X PATCH "https://api.nango.dev/connections/metadata" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "connection_id": "<CONNECTION-ID>",
    "provider_config_key": "<INTEGRATION-ID>",
    "metadata": { "webhookSecret": "<WEBHOOK-SECRET>" }
  }'
```

Use a Nango **Environment API key** from **Environment Settings > API Keys** with the `environment:connections:update` scope. See [Update connection metadata](/reference/backend/http-api/connections/update-metadata) for the full reference.

### 2. Get your Nango webhook URL

In the Nango dashboard, open your Telegram integration and copy the **Webhook URL**. Append `?nangoConnectionId=<CONNECTION-ID>` for the connection you are registering the webhook for. URL-encode the connection ID if it contains characters like `+`, `/` or spaces.

### 3. Set the bot's webhook

Call Telegram's [setWebhook](https://core.telegram.org/bots/api#setwebhook) with the URL from step 2 and the secret from step 1 as `secret_token`. You can call it through the Nango proxy:

```bash
curl -X POST "https://api.nango.dev/proxy/setWebhook" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Connection-Id: <CONNECTION-ID>" \
  -H "Provider-Config-Key: <INTEGRATION-ID>" \
  -H "Content-Type: application/json" \
  -d '{ "url": "<NANGO-WEBHOOK-URL>", "secret_token": "<WEBHOOK-SECRET>" }'
```

A bot has one webhook, and Telegram stops serving `getUpdates` while it is set.

<Note>
The webhook secret on the integration's Settings page is not used for Telegram. Nango only checks the connection's `webhookSecret`.
</Note>

## Handle the webhook

Once routed, you have two options:

- **Forward it to your app**: Nango forwards the event to your webhook URL with connection attribution. See [External webhook forwarding](/guides/triggers/webhook-forwarding).
- **Process it in a sync**: run a sync when the webhook arrives using `webhookSubscriptions` and `onWebhook`. Subscribe to update kinds like `message`. See [Real-time syncs](/guides/syncs/realtime-syncs).

## Rollback strategy

Delete the webhook in Telegram, then clear `webhookSecret` from the connection's metadata by setting it to `null`:

```bash
curl -X PATCH "https://api.nango.dev/connections/metadata" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "connection_id": "<CONNECTION-ID>",
    "provider_config_key": "<INTEGRATION-ID>",
    "metadata": { "webhookSecret": null }
  }'
```

Nango then rejects webhooks for that connection, unless the integration [allows unverified webhooks](/guides/triggers/webhook-forwarding#unverified-webhooks).
