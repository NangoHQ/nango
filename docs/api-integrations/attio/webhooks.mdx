## How it works

Nango routes each Attio webhook event to the connections whose `workspace_id` matches `id.workspace_id`. It then runs every sync on the integration that subscribes to the event type.

Attio record events carry the `object_id` of the object they belong to, for example People or Companies, but not its `api_slug`. Object ids differ per workspace. So if you have one sync for people and one for companies, both subscribed to `record.updated`, every people change also starts the companies sync, and the reverse.

You can tell Nango which object each sync tracks by storing that object's id in the connection metadata. Nango then skips the sync when the event belongs to a different object.

<Note>
This is an extension point, not a configuration Nango manages for you. Nango does not know which object a sync tracks. Your code provides the mapping, per connection.
</Note>

## Setup

For each connection and each sync that handles record webhooks:

1. Call Attio's [list objects](https://docs.attio.com/rest-api/endpoint-reference/objects/list-objects) endpoint with the connection.
2. Find the entry whose `api_slug` matches the object your sync tracks, for example `people` or `companies`. This works for custom objects too.
3. Store its `id.object_id` in the connection metadata under `nango:webhookObjectId:<syncName>`, where `<syncName>` is the name of your sync.

For a `contacts` sync that tracks People and a `companies` sync that tracks Companies:

```json
{
    "nango:webhookObjectId:contacts": "<PEOPLE-OBJECT-ID>",
    "nango:webhookObjectId:companies": "<COMPANIES-OBJECT-ID>"
}
```

A good place to do this is the sync's first run, with `nango.updateMetadata`, which merges keys into the existing metadata.

## What happens when the key is missing or wrong

Nango only skips a sync when the key is present and its value differs from the event's `object_id`. If the key is absent or empty, or the event has no `object_id`, the sync keeps receiving every event it subscribes to, as it does without this setup.

A wrong value is different. If the key holds an id that is not the object your sync tracks, for example one copied from another workspace, the sync stops receiving webhooks for that connection. Store the id read from the same connection, and delete the key if you are unsure of it.

Keep filtering on `object_id` inside `onWebhook` as well, so a missing key only costs extra executions.
