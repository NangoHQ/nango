## How it works

1. PostHog sends a POST request to your Nango webhook URL from a webhook destination, for each event the destination's filters match.
2. Nango looks up the connection named by the `nangoConnectionId` query param on the webhook URL and checks that the `X-Nango-Webhook-Secret` header matches that connection's own webhook secret. PostHog doesn't sign webhooks, so the destination sends the secret as a header.
3. Nango routes the event to that connection, using the payload's `event.event` field, the event name in PostHog's default body, as the webhook type.

PostHog payloads don't say which project they come from, so each connection needs its own webhook in PostHog and its own `webhookSecret` in Nango. Webhooks without the right secret are rejected, unless the connection has no secret and **Allow unverified webhooks** is on in the integration's settings.

## Setup

### 1. Choose a webhook secret

Generate a random secret of at least 16 characters, for example with `openssl rand -hex 24`, and store it as `webhookSecret` in the connection's metadata:

```bash
curl -X PATCH "https://api.nango.dev/connections/metadata" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "connection_id": "<CONNECTION-ID>",
    "provider_config_key": "<INTEGRATION-ID>",
    "metadata": { "webhookSecret": "<WEBHOOK-SECRET>" }
  }'
```

See [Update connection metadata](/reference/backend/http-api/connections/update-metadata) for the full reference.

### 2. Get your Nango webhook URL

In the Nango dashboard, open your PostHog integration and copy the **Webhook URL**. Append `?nangoConnectionId=<CONNECTION-ID>` for the connection you are registering the webhook for. URL-encode the connection ID if it contains characters like `+`, `/` or spaces.

### 3. Add the webhook destination in PostHog

1. In PostHog, go to **Data pipelines** → **Destinations** and add an **HTTP Webhook** destination.
2. Set the webhook URL to the URL from step 2.
3. Add a header named `X-Nango-Webhook-Secret` with the secret from step 1.
4. Keep the default body, or keep its `event` field if you edit it, so the webhook type is the event name.
5. Filter the events to send, and save.

<Note>
The webhook secret on the integration's Settings page is not used for PostHog. Nango only checks the connection's `webhookSecret`.
</Note>

## Handle the webhook

Once routed, you have two options:

- **Forward it to your app**: Nango forwards the event to your webhook URL with connection attribution. See [External webhook forwarding](/guides/triggers/webhook-forwarding).
- **Process it in a sync**: run a sync when the webhook arrives using `webhookSubscriptions` and `onWebhook`. Subscribe to event names like `$pageview`. See [Real-time syncs](/guides/syncs/realtime-syncs).

## Rollback strategy

Delete the webhook in PostHog, then clear `webhookSecret` from the connection's metadata.
