## How it works

1. A PostHog **HTTP Webhook** destination sends a POST request to your Nango webhook URL for each event its filters match.
2. Nango looks up the connection named by the `nangoConnectionId` query param on the webhook URL and verifies the delivery's signature against that connection's own webhook secret. The destination signs deliveries with [Standard Webhooks](https://www.standardwebhooks.com/) when it has a signing secret, and Nango rejects deliveries signed more than 5 minutes ago.
3. Nango routes the event to that connection, using the payload's `event.event` field, the event name in PostHog's default body, as the webhook type.

You choose each destination's signing secret, so each connection needs its own destination in PostHog and its own `webhookSecret` in Nango. Deliveries without a valid signature are rejected, so set a signing secret on the destination.

## Setup

### 1. Choose a signing secret

Generate a random base64 secret of at least 24 bytes, for example with `openssl rand -base64 32`. PostHog and Nango both accept it with or without a `whsec_` prefix.

### 2. Get your Nango webhook URL

In the Nango dashboard, open your PostHog integration and copy the **Webhook URL**. Append `?nangoConnectionId=<CONNECTION-ID>` for the connection you are registering the webhook for. URL-encode the connection ID if it contains characters like `+`, `/` or spaces.

### 3. Create the webhook destination in PostHog

1. In PostHog, go to **Data pipelines**, click **New** → **Destination**, and create an **HTTP Webhook** destination.
2. Set the **Webhook URL** to the URL from step 2 and keep the method as `POST`.
3. Keep the default **JSON Body**, or keep its `event` field if you edit it, so the webhook type is the event name.
4. Set **Signing secret** to the secret from step 1, and keep **Signing format** as **Standard Webhooks**.
5. Filter the events to send, and save.

### 4. Set the webhook secret in Nango

Store the same secret as `webhookSecret` in the connection's metadata:

```bash
curl -X PATCH "https://api.nango.dev/connections/metadata" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "connection_id": "<CONNECTION-ID>",
    "provider_config_key": "<INTEGRATION-ID>",
    "metadata": { "webhookSecret": "<POSTHOG-SIGNING-SECRET>" }
  }'
```

Use a Nango **Environment API key** from **Environment Settings > API Keys** with the `environment:connections:update` scope. See [Update connection metadata](/reference/backend/http-api/connections/update-metadata) for the full reference.

<Note>
The webhook secret on the integration's Settings page is not used for PostHog. Nango only verifies against the connection's `webhookSecret`.
</Note>

## Handle the webhook

Once routed, you have two options:

- **Forward it to your app**: Nango forwards the event to your webhook URL with connection attribution. See [External webhook forwarding](/guides/triggers/webhook-forwarding).
- **Process it in a sync**: run a sync when the webhook arrives using `webhookSubscriptions` and `onWebhook`. Subscribe to event names like `$pageview`. See [Real-time syncs](/guides/syncs/realtime-syncs).

## Rollback strategy

Delete the destination in PostHog, then clear `webhookSecret` from the connection's metadata.
