## How it works

1. Pylon sends a POST request to your Nango webhook URL when a trigger or macro that calls the webhook runs.
2. Nango looks up the connection named by the `nangoConnectionId` query param on the webhook URL and verifies the delivery's `X-Pylon-Signature-V2` against that connection's own webhook secret. The signature is an HMAC-SHA256 of the `X-Pylon-Timestamp` header and the request body, and Nango rejects deliveries signed more than 5 minutes ago. The legacy `X-Pylon-Signature`, which signs the body alone, is not accepted.
3. Nango routes the event to that connection. Pylon webhook bodies are templates you write in a trigger or macro, so they have no event type.

Pylon webhook bodies are templates you write, so they don't say which account they come from. So each connection needs its own webhook in Pylon and its own `webhookSecret` in Nango. Deliveries without a valid signature are rejected.

## Setup

### 1. Get your Nango webhook URL

In the Nango dashboard, open your Pylon integration and copy the **Webhook URL**. Append `?nangoConnectionId=<CONNECTION-ID>` for the connection you are registering the webhook for. URL-encode the connection ID if it contains characters like `+`, `/` or spaces.

### 2. Register the webhook in Pylon

1. In Pylon, go to **Settings** → **Webhooks** and create a webhook with the URL from step 1.
2. Copy the webhook's secret. Pylon only shows it once.
3. Call the webhook from the triggers or macros that should send events.

### 3. Set the webhook secret in Nango

Store the Pylon secret as `webhookSecret` in the connection's metadata:

```bash
curl -X PATCH "https://api.nango.dev/connections/metadata" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "connection_id": "<CONNECTION-ID>",
    "provider_config_key": "<INTEGRATION-ID>",
    "metadata": { "webhookSecret": "<PYLON-WEBHOOK-SECRET>" }
  }'
```

See [Update connection metadata](/reference/backend/http-api/connections/update-metadata) for the full reference.

<Note>
The webhook secret on the integration's Settings page is not used for Pylon. Nango only verifies against the connection's `webhookSecret`.
</Note>

## Handle the webhook

Once routed, you have two options:

- **Forward it to your app**: Nango forwards the event to your webhook URL with connection attribution. See [External webhook forwarding](/guides/triggers/webhook-forwarding).
- **Process it in a sync**: run a sync when the webhook arrives using `webhookSubscriptions` and `onWebhook`. Pylon events have no type, so subscribe with `*`. See [Real-time syncs](/guides/syncs/realtime-syncs).

## Rollback strategy

Delete the webhook in Pylon, then clear `webhookSecret` from the connection's metadata.
