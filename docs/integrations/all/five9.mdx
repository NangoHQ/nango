## Setup guide

<Steps>
    <Step id="find-your-api-region" title="Find your API region">
        Sign in to the Five9 Admin Console and identify your domain's regional API base URL. Select the matching region in Nango:

        | Region | API base URL |
        | - | - |
        | US | `https://api.prod.us.five9.net` |
        | US - Alpha | `https://api.alpha.us.five9.net` |
        | Canada | `https://api.prod.ca.five9.net` |
        | EU | `https://api.prod.eu.five9.net` |
        | India | `https://api.prod.in.five9.net` |
        | UK | `https://api.prod.uk.five9.net` |
    </Step>

    <Step id="create-api-access-control" title="Create API access control">
        In the Admin Console, open **API Access Control** and click **Create**. If the tile is unavailable, contact your Five9 representative because this feature is under controlled availability.

        Select **Client Secret**, then enter a name and contact email. Choose the credential duration, API family, and least-privilege scopes required by your integration. Click **Done**.

        Copy the generated Consumer Key and Consumer Secret immediately. Five9 shows the secret only once.
    </Step>

    <Step id="configure-integration" title="Configure the integration">
        In Nango, create a Five9 integration. Select the API region and enter the Consumer Key and Consumer Secret.

        Nango exchanges these credentials for a bearer token using the OAuth 2.0 client credentials flow.
    </Step>
</Steps>

## API gotchas

- This provider is for Five9's New Platform APIs. API Access Control credentials are distinct from the API Only User used by Core Platform APIs.
- API Access Control and individual API families must be enabled for your Five9 domain.
- Scopes are assigned to the credential in Five9, not requested during the token exchange. Grant only the scopes your integration needs.
- Access tokens are valid for 3,600 seconds and do not include a refresh token. Nango requests another token with the Consumer Key and Consumer Secret when necessary.
- Each API can have at most two active credentials. Credentials may never expire or use a custom expiration date, depending on the duration selected during setup.
- Repeated failed authentication attempts can temporarily lock the associated account.
