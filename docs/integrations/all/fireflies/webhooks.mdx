## How it works

1. Fireflies sends a POST request to your Nango webhook URL when a meeting event happens, for example `meeting.transcribed`.
2. Nango looks up the connection named by the `nangoConnectionId` query param on the webhook URL and verifies the delivery's `X-Hub-Signature` against that connection's own webhook secret. The signature is an HMAC-SHA256 of the request body. Webhooks V2 bodies carry a `timestamp` of when the delivery was sent, and Nango rejects V2 deliveries sent more than 5 minutes ago.
3. Nango routes the event to that connection, using the payload's `event` field (`eventType` for Fireflies' original webhooks) as the webhook type.

Fireflies payloads don't say which account they come from, so each connection needs its own webhook in Fireflies and its own `webhookSecret` in Nango. Deliveries without a valid signature are rejected. A Webhooks V2 signing secret is optional in Fireflies, and Fireflies only signs deliveries when the webhook has one, so set one.

Original (V1) webhook bodies have no timestamp, so Nango can't reject a replayed V1 delivery. Fireflies payloads carry the meeting ID and event details but not the meeting's contents, so fetch the meeting from the Fireflies API before acting on it.

## Setup

### 1. Get your Nango webhook URL

In the Nango dashboard, open your Fireflies integration and copy the **Webhook URL**. Append `?nangoConnectionId=<CONNECTION-ID>` for the connection you are registering the webhook for. URL-encode the connection ID if it contains characters like `+`, `/` or spaces.

### 2. Register the webhook in Fireflies

<Tabs>
  <Tab title="Webhooks V2">
    1. In Fireflies, open the [Webhooks V2 page](https://app.fireflies.ai/integrations/api/webhook) and add a webhook.
    2. Set the URL to the URL from step 1, and pick the events to receive.
    3. Enter a **Signing Secret**. Copy it for step 3.
  </Tab>
  <Tab title="Existing V1 webhook">
    Fireflies no longer lets you create or change V1 webhooks, so create new ones with Webhooks V2. An existing V1 webhook keeps working: its URL must be the one from step 1, and you can read its secret in **Settings** → **Developer settings** → **Webhook** → **View Configuration**.
  </Tab>
</Tabs>

### 3. Set the webhook secret in Nango

Store the Fireflies secret as `webhookSecret` in the connection's metadata:

```bash
curl -X PATCH "https://api.nango.dev/connections/metadata" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "connection_id": "<CONNECTION-ID>",
    "provider_config_key": "<INTEGRATION-ID>",
    "metadata": { "webhookSecret": "<FIREFLIES-WEBHOOK-SECRET>" }
  }'
```

Use a Nango **Environment API key** from **Environment Settings > API Keys** with the `environment:connections:update` scope. See [Update connection metadata](/reference/backend/http-api/connections/update-metadata) for the full reference.

<Note>
The webhook secret on the integration's Settings page is not used for Fireflies. Nango only verifies against the connection's `webhookSecret`.
</Note>

## Handle the webhook

Once routed, you have two options:

- **Forward it to your app**: Nango forwards the event to your webhook URL with connection attribution. See [External webhook forwarding](/guides/triggers/webhook-forwarding).
- **Process it in a sync**: run a sync when the webhook arrives using `webhookSubscriptions` and `onWebhook`. Subscribe to the events your webhook sends, such as `meeting.transcribed` for Webhooks V2 or `Transcription completed` for the original webhook. See [Real-time syncs](/guides/syncs/realtime-syncs).

## Rollback strategy

Delete the webhook in Fireflies' developer settings, then clear `webhookSecret` from the connection's metadata.
