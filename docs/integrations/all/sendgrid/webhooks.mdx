## How it works

1. SendGrid's Event Webhook sends a POST request to your Nango webhook URL with a batch of email events, for example `delivered` and `open`.
2. Nango looks up the connection named by the `nangoConnectionId` query param on the webhook URL and verifies the delivery's `X-Twilio-Email-Event-Webhook-Signature` with that connection's own verification key. SendGrid signs the `X-Twilio-Email-Event-Webhook-Timestamp` header and the request body with ECDSA.
3. Nango routes each event in the batch to that connection, using the event's `event` field as the webhook type.

SendGrid payloads don't say which account they come from, so each connection needs its own Event Webhook in SendGrid and its own verification key in Nango. Deliveries without a valid signature are rejected.

SendGrid retries each failed event for up to 24 hours after it occurred, so Nango accepts a signature for 24 hours (plus a few minutes of clock skew) and rejects older ones. A delivery can arrive more than once within that time, so use each event's `sg_event_id` to ignore events you have already handled.

## Setup

### 1. Get your Nango webhook URL

In the Nango dashboard, open your SendGrid integration and copy the **Webhook URL**. Append `?nangoConnectionId=<CONNECTION-ID>` for the connection you are registering the webhook for. URL-encode the connection ID if it contains characters like `+`, `/` or spaces.

### 2. Register the webhook in SendGrid

1. In SendGrid, go to **Settings** → **Mail Settings** → **Event Webhooks** and create a webhook with the URL from step 1.
2. Pick the events to receive, turn on **Signature Verification**, and click **Save**. SendGrid only generates the key pair when the webhook is saved.
3. Open the webhook again with **Edit** and copy its public **Verification Key**.

<Note>
**Test Integration** sends an unsigned request until the webhook is saved, so Nango rejects it. Test the webhook after saving it.
</Note>

### 3. Set the verification key in Nango

Store the verification key as `webhookSecret` in the connection's metadata:

```bash
curl -X PATCH "https://api.nango.dev/connections/metadata" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "connection_id": "<CONNECTION-ID>",
    "provider_config_key": "<INTEGRATION-ID>",
    "metadata": { "webhookSecret": "<SENDGRID-VERIFICATION-KEY>" }
  }'
```

Use a Nango **Environment API key** from **Environment Settings > API Keys** with the `environment:connections:update` scope. See [Update connection metadata](/reference/backend/http-api/connections/update-metadata) for the full reference.

<Note>
The webhook secret on the integration's Settings page is not used for SendGrid. Nango only verifies with the connection's `webhookSecret`.
</Note>

## Handle the webhook

Once routed, you have two options:

- **Forward it to your app**: Nango forwards the whole batch to your webhook URL with connection attribution. See [External webhook forwarding](/guides/triggers/webhook-forwarding).
- **Process it in a sync**: run a sync when the webhook arrives using `webhookSubscriptions` and `onWebhook`. Each event runs the syncs subscribed to its type, like `delivered`. See [Real-time syncs](/guides/syncs/realtime-syncs).

## Rollback strategy

Delete the Event Webhook in SendGrid, then clear `webhookSecret` from the connection's metadata.
