## How it works

1. incident.io sends a POST request to your Nango webhook URL when one of the events you picked happens, for example `public_incident.incident_created_v2`.
2. Nango looks up the connection named by the `nangoConnectionId` query param on the webhook URL and verifies the delivery's signature against that connection's own webhook secret. incident.io signs deliveries with [Standard Webhooks](https://www.standardwebhooks.com/), and Nango rejects deliveries signed more than 5 minutes ago.
3. Nango routes the event to that connection, using the payload's `event_type` field as the webhook type.

incident.io payloads don't say which account they come from, so each connection needs its own webhook endpoint in incident.io and its own `webhookSecret` in Nango. Deliveries without a valid signature are rejected. incident.io sends the incident in the payload, but fetch it from the incident.io API if you need its latest state.

## Setup

### 1. Get your Nango webhook URL

In the Nango dashboard, open your incident.io integration and copy the **Webhook URL**. Append `?nangoConnectionId=<CONNECTION-ID>` for the connection you are registering the webhook for. URL-encode the connection ID if it contains characters like `+`, `/` or spaces.

### 2. Register the webhook in incident.io

1. In incident.io, go to **Settings** → **Webhooks** and add an endpoint.
2. Set the URL to the URL from step 1, and pick the events to receive.
3. Open the endpoint and copy its **Signing secret** (it starts with `whsec_`).

### 3. Set the webhook secret in Nango

Store the whole signing secret, including `whsec_`, as `webhookSecret` in the connection's metadata:

```bash
curl -X PATCH "https://api.nango.dev/connections/metadata" \
  -H "Authorization: Bearer <NANGO-API-KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "connection_id": "<CONNECTION-ID>",
    "provider_config_key": "<INTEGRATION-ID>",
    "metadata": { "webhookSecret": "<INCIDENT-IO-SIGNING-SECRET>" }
  }'
```

Use a Nango **Environment API key** from **Environment Settings > API Keys** with the `environment:connections:update` scope. See [Update connection metadata](/reference/backend/http-api/connections/update-metadata) for the full reference.

<Note>
The webhook secret on the integration's Settings page is not used for incident.io. Nango only verifies against the connection's `webhookSecret`.
</Note>

## Handle the webhook

Once routed, you have two options:

- **Forward it to your app**: Nango forwards the event to your webhook URL with connection attribution. See [External webhook forwarding](/guides/triggers/webhook-forwarding).
- **Process it in a sync**: run a sync when the webhook arrives using `webhookSubscriptions` and `onWebhook`. Subscribe to event types like `public_incident.incident_created_v2`. See [Real-time syncs](/guides/syncs/realtime-syncs).

## Rollback strategy

Delete the endpoint in incident.io, then clear `webhookSecret` from the connection's metadata.
