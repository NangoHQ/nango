**Note**
- This provider is for [Link's Agent Wallet](https://docs.stripe.com/agentic-commerce/agents/link-agent-wallet/oauth): a consumer authorizes your agent to access their Link wallet, so the agent can create spend requests and retrieve scoped payment credentials or financial data on their behalf.
- The Link API lives at `api.link.com` and authorizes against `login.link.com`. It is separate from the Stripe API at `api.stripe.com`: Stripe secret or restricted API keys do not authenticate requests here, only the per-customer OAuth access token does.
- Want to integrate with a merchant's Stripe account instead? Use [Stripe App](/integrations/all/stripe-app) or [Stripe (API Key)](/api-integrations/stripe-api-key).

| Pre-Requisites    | Status         | Comment                                                                                                              |
| ----------------- | -------------- | --------------------------------------------------------------------------------------------------------------------- |
| Paid dev account  | ✅ Not required | Agent payments don't require a Stripe account. Financial insights scopes require a Stripe account registered for [Financial Connections](https://docs.stripe.com/financial-connections). |

## Setup guide

<Steps>
  <Step title="Register an OAuth client with Stripe">
    Follow the [Link Agent Wallet OAuth guide](https://docs.stripe.com/agentic-commerce/agents/link-agent-wallet/oauth) to register an OAuth client:
    1. Provide your application name and description.
    2. Register your redirect URI as `https://api.nango.dev/oauth/callback`. Redirect URIs are matched exactly at authorization time.
    3. Stripe sends you a `client_id` and `client_secret`.
  </Step>

  <Step title="Choose your scopes">
    Request only the scopes your agent needs. For agent payments the typical pair is `payment_methods.agentic` and `userinfo:read`. The full list is published in Link's [authorization server metadata](https://login.link.com/.well-known/oauth-authorization-server).
  </Step>

  <Step title="Next">
    Follow the [_Quickstart_](/getting-started/quickstart).
  </Step>
</Steps>

## API gotchas

- Refresh tokens rotate: every refresh response contains a new `refresh_token` and invalidates the one you sent. Nango handles this automatically, but don't reuse tokens outside Nango.
- The token response echoes the `scope` the customer actually granted, which can be a subset of what you requested. Read it instead of assuming the full request was approved.
- The authorization URL accepts an optional `key` parameter (your Stripe publishable key). It is required for financial insights flows, which initiate through Financial Connections.
