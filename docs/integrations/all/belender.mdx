  <Tab title="🚀 Quickstart">
    <Steps>
      <Step title="Create an integration">
        In Nango ([free signup](https://app.nango.dev)), go to **Integrations** → _Configure New Integration_ → _Belender_.
      </Step>
      <Step title="Authorize Belender">
        Go to **Connections** → _Add Test Connection_ → _Authorize_, then enter your Belender API hostname, email, and password. Later, you'll let your users do the same directly from your app.
      </Step>
      <Step title="Call the Belender API">
        Fetch standardized document JSON for a Belender request. `request_id` is returned when you create a request (for example via `POST /requests/clave-pin` or `POST /requests/sms`) or from Belender webhooks. Replace the placeholders below with your [Environment API key](/reference/backend/http-api/api-keys), integration ID, connection ID, and that `request_id`:
        <Tabs>
            <Tab title="cURL">

                ```bash
                REQUEST_ID="00000000-0000-0000-0000-000000000000"

                curl "https://api.nango.dev/proxy/requests/${REQUEST_ID}/fast-json" \
                  -H "Authorization: Bearer <NANGO-API-KEY>" \
                  -H "Provider-Config-Key: <INTEGRATION-ID>" \
                  -H "Connection-Id: <CONNECTION-ID>"
                ```

            </Tab>

            <Tab title="Node">

            Install Nango's backend SDK with `npm i @nangohq/node`. Then run:

            ```typescript
            import { Nango } from '@nangohq/node';

            const nango = new Nango({ apiKey: '<NANGO-API-KEY>' });
            const requestId = '00000000-0000-0000-0000-000000000000';

            const res = await nango.get({
                endpoint: `/requests/${requestId}/fast-json`,
                providerConfigKey: '<INTEGRATION-ID>',
                connectionId: '<CONNECTION-ID>'
            });

            console.log(res.data);
            ```
            </Tab>

        </Tabs>

        Or fetch credentials dynamically via the [Node SDK](/reference/backend/backend-sdk/node#get-a-connection-with-credentials) or [API](/reference/backend/http-api/connections/get).

      </Step>
    </Steps>

    ✅ You're connected! Check the **Logs** tab in Nango to inspect requests.

    <Tip>
    Next step: [Embed the auth flow](/guides/primitives/auth) in your app to let your users connect their Belender accounts.
    </Tip>
  </Tab>
  <Tab title="📚 API reference">
    Belender does not publish a full public OpenAPI catalogue. The endpoints below are the documented HTTP surface used for production integrations against `https://api.belender.net` (prod) and `https://api.qa.belender.net` (QA). Product overview: [belender.eu](https://belender.eu/).

    Auth (`POST /login`) is handled by Nango’s `TWO_STEP` flow when you create a connection. Proxy calls receive an `Authorization: Bearer` header with the stored access token.

    ### Authentication

    | Method | Path | Body | Notes |
    | - | - | - | - |
    | `POST` | `/login` | `{ "email", "password" }` | Returns `access_token`. Used by Nango on connect; you normally do not call this via the proxy. |

    ### Document / certificate flows (multipart)

    These create Belender requests that collect end-user consent and later deliver official documents (CIRBE, tax, social security, etc.).

    | Method | Path | Content-Type | Purpose |
    | - | - | - | - |
    | `POST` | `/requests/client-certificate` | `multipart/form-data` | Legal-entity flow with ID document images + company data. |
    | `POST` | `/requests/videoid` | `multipart/form-data` | Natural-person video-ID flow. |
    | `POST` | `/digital-power/send-job` | `multipart/form-data` | Digital power of attorney job for a company CIF. |

    Common multipart fields (vary by flow): `user_id`, `package_id`, `name`, `first_surname`, `second_surname`, `email_copy`, `phone`, `document_number`, `company_name`, `cif`, `power_activate`, `document_front`, `document_back`, `type` (`legal` / `natural`).

    ```typescript
    // Example: start a digital-power job (multipart)
    const formData = new FormData();
    formData.append('package_id', '<PACKAGE-ID>');
    formData.append('cif', 'B12345678');
    formData.append('type', 'legal');
    // Append additional fields / file blobs required by the flow (document_front, document_back, ...).

    const res = await nango.post({
        endpoint: '/digital-power/send-job',
        providerConfigKey: '<INTEGRATION-ID>',
        connectionId: '<CONNECTION-ID>',
        headers: { 'Content-Type': 'multipart/form-data' },
        data: formData
    });
    ```

    ### Cl@ve PIN flow (JSON)

    | Method | Path | Purpose |
    | - | - | - |
    | `POST` | `/requests/clave-pin/check-service` | Check whether the person has Cl@ve PIN (`document_number`, `document_expiration_date`, optional `document_support` for NIE). |
    | `POST` | `/requests/clave-pin` | Create Cl@ve PIN request (`package_id`, `check_legal`, document fields). |
    | `POST` | `/requests/clave-pin/terms` | Accept terms (`request_id`, `terms_and_conditions`). |
    | `POST` | `/requests/clave-pin/otp` | Submit OTP (`request_id`, `code`). |
    | `POST` | `/requests/clave-pin/resend-otp` | Resend OTP (`request_id`). |

    ```typescript
    const check = await nango.post({
        endpoint: '/requests/clave-pin/check-service',
        providerConfigKey: '<INTEGRATION-ID>',
        connectionId: '<CONNECTION-ID>',
        data: {
            document_number: '12345678Z',
            document_expiration_date: '2030-01-15'
        }
    });

    const created = await nango.post({
        endpoint: '/requests/clave-pin',
        providerConfigKey: '<INTEGRATION-ID>',
        connectionId: '<CONNECTION-ID>',
        data: {
            document_number: '12345678Z',
            document_expiration_date: '2030-01-15',
            package_id: '<PACKAGE-UUID>',
            check_legal: true
        }
    });
    ```

    ### SMS flow (JSON)

    | Method | Path | Purpose |
    | - | - | - |
    | `POST` | `/requests/sms` | Create SMS verification request (`document_number`, `phone`, `birth_date`, `package_id`, `check_legal`). |
    | `POST` | `/requests/sms/terms` | Accept terms (`request_id`, `terms_and_conditions`). |
    | `POST` | `/requests/sms/otp` | Submit OTP (`request_id`, `code`). |
    | `POST` | `/requests/sms/resend-otp` | Resend OTP (`request_id`). |

    ### Retrieve documents / data

    | Method | Path | Purpose |
    | - | - | - |
    | `GET` | `/requests/{request_id}/documents/{document_id}` | Download a specific document produced by a request. |
    | `GET` | `/requests/{request_id}/fast-json` | Fetch Belender’s standardized JSON payload for the request (e.g. AEAT / SS). |

    ```typescript
    const doc = await nango.get({
        endpoint: `/requests/${requestId}/documents/${documentId}`,
        providerConfigKey: '<INTEGRATION-ID>',
        connectionId: '<CONNECTION-ID>'
    });

    const fastJson = await nango.get({
        endpoint: `/requests/${requestId}/fast-json`,
        providerConfigKey: '<INTEGRATION-ID>',
        connectionId: '<CONNECTION-ID>'
    });
    ```

    ### Async lifecycle (webhooks)

    Belender notifies progress via webhooks (configure the callback URL with Belender). Typical `status_code` / `document_status_code` values include:

    `terms_and_conditions`, `waiting_password`, `waiting_otp`, `waiting_video`, `approved_terms_digital_power`, `waiting_acceptance_file_signed`, `cert_approved`, `waiting_certificate`, `consent_process_completed`, `certificate_created`, `approved_digital_power`, `waiting_documents`, `fast_json_ss`, `fast_json_aeat`, `downloaded`, `all_documents_downloaded`, `declined_terms_digital_power`, `rejected_identity`, `rejected_rmc_validation`, `failed_without_retry`, `failed_download`.

    After relevant statuses, pull documents with `GET /requests/{id}/documents/{document_id}` and/or `GET /requests/{id}/fast-json`.

    ### Packages

    Most create-request calls require a Belender `package_id` (UUID) assigned to your account for each product pack. Obtain package IDs from Belender (they differ between QA and production).

    ### Pre-built actions

    JSON flows and document retrieval (multipart certificate / video-id / digital-power stay on the proxy):

    | Action | Group | Purpose |
    | - | - | - |
    | `check-clave-pin-service` | Clave PIN | Check Cl@ve PIN availability. |
    | `create-clave-pin-request` | Clave PIN | Start Cl@ve PIN request. |
    | `accept-clave-pin-terms` | Clave PIN | Accept terms. |
    | `submit-clave-pin-otp` | Clave PIN | Submit OTP. |
    | `resend-clave-pin-otp` | Clave PIN | Resend OTP. |
    | `create-sms-request` | SMS | Start SMS verification. |
    | `accept-sms-terms` | SMS | Accept terms. |
    | `submit-sms-otp` | SMS | Submit OTP. |
    | `resend-sms-otp` | SMS | Resend OTP. |
    | `get-fast-json` | Documents | Fetch standardized JSON. |
    | `get-document` | Documents | Download a request document. |

    Trigger with the [Actions API](/guides/functions/action-functions) or Node SDK: `nango.triggerAction('<INTEGRATION-ID>', '<CONNECTION-ID>', 'get-fast-json', { request_id: '00000000-0000-0000-0000-000000000000' })`. Source: `integration-templates/integrations/belender/actions/`.

  <Tab title="🚨 API gotchas">
    - Belender issues a bearer `access_token` via `POST /login` with JSON `{ email, password }`. Nango stores that token and injects `Authorization: Bearer …` on proxy calls.
    - Use hostname `api.belender.net` for production and `api.qa.belender.net` for QA (connection config `hostname`, no scheme).
    - Multipart endpoints (`/requests/client-certificate`, `/requests/videoid`, `/digital-power/send-job`) require a real `multipart/form-data` body when calling through the proxy.
    - Cl@ve PIN and SMS step endpoints are JSON (`/terms`, `/otp`, `/resend-otp`) and need the Belender `request_id` from the create-request response.
    - `package_id` is environment-specific; do not reuse production package IDs against QA.
    - Document download and consent completion are asynchronous — drive the flow from Belender webhooks, then fetch documents / fast-json.

    <Note>Contribute API gotchas by [editing this page](https://github.com/nangohq/nango/tree/master/docs/integrations/all/belender.mdx)</Note>
